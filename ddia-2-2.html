📖 Recap — Parte 2.1

Cubrimos el modelo relacional (Codd 1970), el boom NoSQL (2009), el impedance mismatch entre OO y SQL, las fortalezas del modelo documental (one-to-many, localidad), las debilidades (many-to-many), la diferencia entre schema-on-write y schema-on-read, y por qué SQL declarativo permite mejores optimizaciones que código imperativo. Ahora: cuando los datos son altamente conectados, hay un tercer modelo — el de grafos.

🕸️ ¿Por qué un modelo de Grafo?

El modelo relacional maneja well many-to-many pero se complica cuando las relaciones entre datos son el dato principal. Considera:

  • Redes sociales: personas conectadas con personas — who follows whom, mutual friends
  • Web: páginas conectadas con páginas mediante hyperlinks — PageRank de Google
  • Rutas: intersecciones conectadas por carreteras — GPS, mapas, Waze
  • Dependencias: paquetes que dependen de paquetes — npm, Maven
  • Knowledge graphs: "Madrid es la capital de España, que está en Europa"

En todos estos, las relaciones son tan importantes como los nodos. Un grafo es la representación natural.

Componentes del Grafo de Propiedad

Un grafo de propiedad tiene dos tipos de objetos — vértices (nodos) y aristas (edges). Cada uno tiene:

  • Un identificador único
  • Un conjunto de propiedades (key-value pairs)
  • Para aristas: un nodo de inicio, un nodo de fin, y un label describiendo la relación

Las aristas son dirigidas (tienen dirección) pero puedes traversarlas en ambas direcciones. No hay esquema fijo: cualquier vértice puede conectarse con cualquier vértice mediante cualquier tipo de arista. Esto da una flexibilidad que SQL no puede igualar fácilmente.

⚡ Cypher — Query Language para Grafos (Neo4j)

Cypher es el lenguaje de Neo4j. Usa una sintaxis visual ASCII para describir patrones de grafo: (nodo)-[:RELACIÓN]->(nodo).

Crear el grafo

// Crear vértices y aristas en Cypher
CREATE (alex:Person {name: 'Alex', born: 1995})
CREATE (santiago:City {name: 'Santiago'})
CREATE (chile:Country {name: 'Chile'})
CREATE (meli:Company {name: 'MercadoLibre'})

CREATE (alex)-[:BORN_IN]->(santiago)
CREATE (alex)-[:WORKS_AT {since: 2022}]->(meli)
CREATE (santiago)-[:WITHIN]->(chile)

Query: ¿Quiénes emigraron de América Latina a Europa?

// Encuentra personas nacidas en América Latina que ahora viven en Europa
MATCH
  (person:Person)-[:BORN_IN]->(birthplace:Location),
  (birthplace)-[:WITHIN*0..]->(latam:Region {name:'Latin America'}),
  (person)-[:LIVES_IN]->(residence:Location),
  (residence)-[:WITHIN*0..]->(europe:Region {name:'Europe'})
RETURN person.name
La magia de WITHIN*0..]: el asterisco indica traversal recursivo — puede seguir la cadena Santiago → Chile → América Latina sin importar cuántos niveles tenga la jerarquía. En SQL necesitarías WITH RECURSIVE, que es mucho más verboso.

¿Por qué Cypher es más expresivo que SQL para grafos?

En SQL para encontrar "emigrantes de LatAm a Europa" necesitarías joins recursivos con WITH RECURSIVE, que el DB puede o no ejecutar eficientemente. En Cypher, el patrón visual captura exactamente la semántica: la sintaxis parece el grafo que estás describiendo.

🔁 Grafos en SQL: WITH RECURSIVE

¿Puedes representar un grafo en SQL? Sí — vértices en una tabla, aristas en otra. ¿Puedes hacer queries de grafo en SQL? También sí, pero con WITH RECURSIVE, que es verboso y difícil de leer.

-- El mismo query de "dentro de región" en SQL puro:
WITH RECURSIVE in_usa(vertex_id) AS (
    -- Caso base: la región "Latin America" misma
    SELECT vertex_id FROM vertices WHERE properties->>'name' = 'Latin America'
  UNION
    -- Paso recursivo: cualquier lugar dentro de un lugar ya incluido
    SELECT edges.tail_vertex
    FROM edges
    JOIN in_usa ON edges.head_vertex = in_usa.vertex_id
    WHERE edges.label = 'within'
)
SELECT vertices.* FROM vertices, in_usa
WHERE in_usa.vertex_id = vertices.vertex_id
AND vertices.type = 'person';

Funciona. Pero compara con el Cypher: 3 líneas vs 15. El modelo de grafo no es solo una base de datos diferente — es un modelo de pensamiento diferente que se refleja en la concisión del lenguaje de query.

📐 Triple-Stores y RDF

Las triple-stores usan una forma de representación diferente al grafo de propiedad: cada dato es un triple de tres partes: (sujeto, predicado, objeto).

  • Sujeto: equivale a un vértice del grafo
  • Predicado: equivale al label de la arista o una propiedad
  • Objeto: puede ser un valor primitivo (string, número) o otro vértice
# Turtle syntax (RDF)
@prefix :  .

:Alex a :Person ;
    :name "Alex" ;
    :bornIn :Santiago .

:Santiago a :City ;
    :within :Chile .

:Chile a :Country ;
    :within :LatinAmerica .
RDF y la Web Semántica: Tim Berners-Lee (creador de HTTP) tenía la visión de una "Web Semántica" donde toda la información en internet estaría en formato RDF, permitiendo a las máquinas "entender" el contenido. Fue un proyecto ambicioso que nunca despegó masivamente, pero el formato RDF y SPARQL siguen usándose en knowledge graphs (DBpedia, Wikidata).

SPARQL — Query para Triple-Stores

# El mismo query de emigrantes en SPARQL
PREFIX : 

SELECT ?personName
WHERE {
  ?person :name ?personName ;
          :bornIn / :within* :LatinAmerica ;
          :livesIn / :within* :Europe .
}

SPARQL usa el patrón / para traversal de paths y * para recursión — similar conceptualmente a Cypher pero con sintaxis derivada de SPARQL Protocol.

🧮 Datalog — El Ancestro Declarativo

Datalog es más antiguo que Cypher o SPARQL — tiene raíces en Prolog (1970s) y fue estudiado académicamente en los 80s. Datomic (la DB de Rich Hickey) lo usa. Es poderoso porque permite definir reglas reutilizables — como funciones, pero declarativas.

En Datalog, los datos se expresan como predicados:

% Datos (hechos)
within(santiago, chile).
within(chile, latin_america).
born_in(alex, santiago).
lives_in(alex, berlin).
within(berlin, germany).
within(germany, europe).
% Reglas (como funciones recursivas)
% within_recursive(Lugar, Region) es verdad si:
within_recursive(Location, Region) :-
    within(Location, Region).                % caso base directo

within_recursive(Location, Region) :-
    within(Location, Via),                   % hay un lugar intermedio
    within_recursive(Via, Region).           % que recursivamente está en Region

% Query: personas nacidas en LatAm que viven en Europa
migrant(Name) :-
    born_in(Person, BirthPlace),
    within_recursive(BirthPlace, latin_america),
    lives_in(Person, Residence),
    within_recursive(Residence, europe),
    person_name(Person, Name).
Ventaja de Datalog: las reglas se pueden componer y reutilizar. within_recursive es como una función que usás en múltiples queries. En SQL con WITH RECURSIVE tenés que reescribir la recursión cada vez. Datalog fomenta la abstracción.

¿Por qué importa entender Datalog?

Muchos sistemas modernos tienen partes inspiradas en Datalog: Apache Spark (RDDs), sistemas de reglas de negocios, algunos query planners. Entender que hay más paradigmas de query que SQL te da perspectiva cuando evalúas herramientas.

🗺️ Comparación: ¿Cuándo usar qué modelo?

Insight clave del capítulo 2: No existe un modelo de datos que sea el mejor para todos los casos. Las bases de datos relacionales siguen siendo la opción predeterminada y razonable para la mayoría de casos. Los modelos documentales y de grafo existen porque hay clases de problemas donde el modelo relacional es torpe, no porque el relacional sea malo.

📚 Glosario

Grafo de Propiedad
Modelo donde datos son vértices y aristas (dirigidas, con label y propiedades). Neo4j. Ideal para datos altamente conectados.
Cypher
Lenguaje de query de Neo4j. Sintaxis ASCII visual: (nodo)-[:RELACIÓN]->(nodo). Soporta traversal recursivo con *.
Triple-Store
Almacena datos como triples (sujeto, predicado, objeto). Datomic, Virtuoso. Base de la Web Semántica de Berners-Lee.
RDF
Resource Description Framework. Estándar W3C para triples. Formato Turtle: :Subject :predicate :Object. SPARQL para queries.
SPARQL
Query language para RDF/triple-stores. Usa patrones de grafos y path expressions. Análogo a Cypher para Neo4j.
Datalog
Lenguaje declarativo basado en Prolog. Define reglas reutilizables recursivamente. Usado en Datomic, inspiró muchos query optimizers.
WITH RECURSIVE
Extension de SQL estándar para queries recursivos. Permite traversar jerarquías en grafos. Verboso comparado con Cypher.
Knowledge Graph
Representación de conocimiento como grafo. Wikidata, Google Knowledge Graph. Triples o grafos de propiedad. Permite inferencia semántica.
